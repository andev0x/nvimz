# Architecture

This document describes the design principles, loading pipeline, and internal file and module structure of **nvimz**.

## Core Design Principles

**nvimz** is designed as a native-first, zero-bloat Neovim configuration. It optimizes performance and maintainability by adhering to the following rules:

1. **System-Managed Dependencies:** Language servers, formatters, and compilers are expected to be available on your system `$PATH` rather than isolated inside Neovim via third-party managers like Mason.
2. **Ecosystem Unification:** Prefers the cohesive, lightweight `mini.nvim` suite over numerous single-purpose plugins to reduce API fragmentation.
3. **Local Compilation:** Tree-sitter parsers use pinned or upstream-tracked revisions and are compiled locally from source to guarantee syntax stability.

## Phase-Driven Loading Pipeline

To achieve a sub-10ms startup time, **nvimz** employs a strategic 3-phase loading mechanism. This ensures that the core initialization path (processing keymaps, basic options, and the first render) is never blocked by plugin setup.

```
[Startup] -> Load Core Config -> First Screen Render
                                      │
                                      ▼
                         VimEnter (deferred via vim.defer_fn)
                         ├── [Phase 1: UI + Core]
                         │   Theme, Icons, Statusline, Scope line, Treesitter,
                         │   LSP, oil.nvim, mini.* editing, picker, Git
                         └── [Phase 2: Format + Debug]
                             conform.nvim, nvim-dap + UI + nvim-dap-go
                                      │
                                      ▼
                         InsertEnter (once)
                         [Phase 3: AI]
                         gp.nvim (Ollama), copilot.lua

                         FileType=markdown (once)
                         [Markdown rendering]
                         render-markdown.nvim
```

### 1. UI + Core Phase
Deferred until `VimEnter`, then scheduled with `vim.defer_fn(..., 0)`.
* **Modules:** Theme (`tokyonight`), Icons (`mini.icons`), Statusline (`mini.statusline`), scope line, Tree-sitter, LSP (`vim.lsp`), completion (`mini.completion`), pairs (`mini.pairs`), `oil.nvim`, native picker, Git (`mini.git`, `mini.diff`).
* **Goal:** Deliver an immediate first screen, then initialize everything needed for editing in the background.

### 2. Format + Debug Phase
Also deferred until `VimEnter`.
* **Modules:** Formatting (`conform.nvim`), debugging (`nvim-dap`, `nvim-dap-ui`, `nvim-nio`, `nvim-dap-go`).
* **Goal:** Keep formatting and DAP out of the critical startup path.

### 3. AI Phase
Triggered lazily on the first `InsertEnter`.
* **Modules:** AI utilities (`gp.nvim` with Ollama agents, `copilot.lua`).
* **Goal:** Keep AI plugins entirely unloaded until you actually start editing.

Markdown rendering (`render-markdown.nvim`) is loaded only on `FileType=markdown`. The dashboard is initialized on `VimEnter` for interactive sessions.

## Centralized Package Management

**nvimz** uses Neovim's built-in `vim.pack` directly. There is no custom package manager: plugin sources are declared in `lua/nvimz/config/plugins.lua`, and installation, updates, the lockfile, and rollback are handled natively by `vim.pack`.

### Orchestration Layer

* **`lua/nvimz/config/plugins.lua`:** Declares the plugins for each loading phase using native `vim.pack` specs.
* **`lua/runtime/phases.lua`:** Adds the plugins with `vim.pack.add` and runs each phase's setup, isolating and reporting failures per module.
* **`nvim-pack-lock.json`:** Written and read by `vim.pack` itself. Revisions are never generated by custom code.
* **`scripts/manage --update`:** Runs `vim.pack.update(nil, { force = true })` headlessly, then rebuilds parsers. Interactive updates use `:PackUpdate`, which opens the native review buffer.
* **`scripts/parsers`:** Compiles pinned or upstream-tracked Tree-sitter parsers directly from source and syncs optimized queries to the root `queries/` directory.
* **`scripts/setup`:** A universal bootstrapping script that detects the host operating system, configures required toolchains, and installs runtime dependencies.

### Key Orchestration Features

* **Reviewed Updates:** `:PackUpdate` shows the native `vim.pack` confirmation buffer; nothing changes until `:write`. `:PackRollback` opens the same review buffer targeting the lockfile revisions; `:write` restores them, `:quit` discards.
* **Decoupled Queries:** Tree-sitter queries are maintained directly in the root `queries/` directory, preventing upstream plugin updates from breaking custom syntax highlights.
* **Native Diagnostics:** `:checkhealth nvimz` reports tools, servers, formatters, parsers, plugins, and machine configuration without spawning child Neovim processes or writing state.

## Customization & Local Overrides

**nvimz** provides a clean extension interface designed to separate shared configuration from host-specific environments.

### Local Machine Overrides

Host-specific overrides (such as a localized Python host path) are declared in `lua/machine/local.lua`. This file is ignored by Git, allowing you to tailor settings on individual work or personal machines without polluting the shared repository.

An example configuration file is provided in `lua/machine/example.lua`:

```lua
return {
    -- Override executable paths
    python_path = "/usr/bin/python3",
}
```

To create your local configuration manually:

```bash
cp lua/machine/example.lua lua/machine/local.lua
```
