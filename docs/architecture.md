# Architecture

This document describes the design principles, loading pipeline, and internal file and module structure of **nvimz**.

## Core Design Principles

**nvimz** is designed as a native-first, zero-bloat Neovim configuration. It optimizes performance and maintainability by adhering to the following rules:

1. **System-Managed Dependencies:** Language servers, formatters, and compilers are expected to be available on your system `$PATH` rather than isolated inside Neovim via third-party managers like Mason.
2. **Ecosystem Unification:** Prefers the cohesive, lightweight `mini.nvim` suite over numerous single-purpose plugins to reduce API fragmentation.
3. **Local Compilation:** Tree-sitter parsers use pinned or upstream-tracked revisions and are compiled locally from source to guarantee syntax stability.

---

## Tiered Loading Pipeline

Plugins are added at the boundary where they first matter, so the core path (options, keymaps, commands, and event handlers) never waits for plugin setup. There is no timer chain and no background scheduler.

| Tier | Trigger | Work |
| --- | --- | --- |
| **0 — Core** | `init.lua` (synchronous) | Version guard, options, keymaps, commands, autocmds. No plugin setup or subprocess. |
| **1 — First render** | `VimEnter` (synchronous) | `tokyonight`, `mini.nvim`, theme, icons, statusline, first-buffer Treesitter, the dashboard when no file was given, and Markdown rendering when the first buffer is Markdown. The native intro screen is never shown. |
| **2 — Normal editing** | First relevant event | Pairs and completion on the first `InsertEnter`; scope line and Git signs on the first cursor movement in a real editing buffer; `conform.nvim` on the first write; LSP on the first code `FileType`; Oil from its key, `:Oil`, or a directory startup. |
| **3 — On demand** | First use | DAP on the first `<leader>d*`/`:Dap*`; `gp.nvim` on the first AI key/`:Gp*`; Copilot on `<leader>at`/`:Copilot`; the picker on its key; Markdown for listed Markdown files. Plugin-owned `nofile` floats such as an LSP hover are excluded. |
| **4 — Idle** | — | None: no warm-up, periodic timer, or speculative preload. |

Treesitter is the only feature that must start on the first buffer, because waiting would cause a visible switch from native syntax to parsed highlighting. Markdown rendering follows the same rule for user-edited Markdown buffers.

## Centralized Package Management

**nvimz** uses Neovim's built-in `vim.pack` directly. There is no custom package manager: plugin sources are declared in `lua/nvimz/config/plugins.lua`, and installation, updates, the lockfile, and rollback are handled natively by `vim.pack`.

### Orchestration Layer

* **`lua/nvimz/config/plugins.lua`:** Declares the plugins for each loading tier using native `vim.pack` specs.
* **`lua/runtime/phases.lua`:** Adds plugins with `vim.pack.add` at the right trigger and runs each feature's setup, isolating and reporting failures per module.
* **`nvim-pack-lock.json`:** Written and read by `vim.pack` itself. Revisions are never generated by custom code.
* **`scripts/manage --update`:** Runs `vim.pack.update(nil, { force = true })` headlessly, then rebuilds parsers. Interactive updates use `:PackUpdate`, which opens the native review buffer.
* **`scripts/parsers`:** Compiles pinned or upstream-tracked Tree-sitter parsers directly from source and syncs optimized queries to the root `queries/` directory.
* **`scripts/setup`:** A universal bootstrapping script that detects the host operating system, configures required toolchains, and installs runtime dependencies.

### Key Orchestration Features

* **Reviewed Updates:** `:PackUpdate` shows the native `vim.pack` confirmation buffer; nothing changes until `:write`. `:PackRollback` opens the same review buffer targeting the lockfile revisions; `:write` restores them, `:quit` discards.
* **Decoupled Queries:** Tree-sitter queries are maintained directly in the root `queries/` directory, preventing upstream plugin updates from breaking custom syntax highlights.
* **Native Diagnostics:** `:checkhealth nvimz` reports tools, servers, formatters, parsers, plugins, and machine configuration without spawning child Neovim processes or writing state.

## Repository Layout

```
init.lua                 # records start time -> require("runtime")
lua/
  runtime/               # version guard, core orchestration, event triggers
  core/                  # options, keymaps (<Space> leader), autocmds, commands, filetypes
  features/              # interface/, lsp/, editing/, git/, format/, dap/, ai/
  nvimz/
    config/              # plugins, languages, tools, parsers (static declarations)
    picker/              # native fuzzy picker implementation
    health.lua           # :checkhealth nvimz provider
    packages.lua         # status/clean helpers over vim.pack
    benchmark.lua        # :NvimzBenchmark
    treesitter.lua       # native Treesitter + folds
    ui.lua               # scratch report buffers
  machine/               # host-local overrides (copy example.lua -> local.lua, gitignored)
scripts/                 # setup, manage, doctor, parsers, lang/, lib/
queries/                 # decoupled Treesitter queries
ftplugin/                # per-filetype overrides (Java)
docs/                    # installation, architecture, performance, commands, languages, audit/
nvim-pack-lock.json      # pinned plugin revisions
```
